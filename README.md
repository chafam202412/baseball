# 야구 기록장

경기별 타석·투구·수비와 칼럼을 기록하는 한국어 개인 야구 아카이브입니다.

## 구성

- `index.html`: 화면과 기록·집계 로직. 기존 브라우저 저장 및 GitHub 동기화 방식을 사용합니다.
- `design-refresh.css`: 반응형 화면, 핵심 요약, 상세 접기/펼치기의 시각 스타일.
- `data.json`: 공개 화면이 읽는 기록. 코드 테스트에서 수정하지 않습니다.
- `draft-2023-2026.html`: 최신 드래프트 자료로 연결하는 기존 주소.
- `CNAME`, `robots.txt`: 기존 도메인과 검색로봇 설정.

GitHub Pages에서 정적 파일을 제공하며 별도 빌드나 패키지 설치가 필요하지 않습니다.

## 회귀 테스트

Node.js 20 이상에서 실행합니다. 합성 데이터만 사용하며 GitHub에 요청하거나 실제 기록을 수정하지 않습니다.

```sh
node --test tests/*.test.cjs
```

테스트는 빈 타석 처리, 야구 지표 계산, 같은 날 투구수 합산, 훈련 수정/취소, 백업 병합, 콘텐츠 URL 처리 등을 확인합니다. 보안 테스트는 `qa-preview/security-fixture.html`도 생성합니다. 이 파일을 로컬 미리보기에서 열면 실제 브라우저 DOM의 HTML 정리 동작을 추가 확인할 수 있습니다.

## 유지보수 시 주의

- `data.json`은 사용자 기록입니다. 디자인·기능 변경 시 그대로 보존하세요.
- 동기화 구조는 이번 화면 개편에서 변경하지 않았습니다. 저장소 파일 충돌과 오프라인 미전송 데이터의 기존 제약은 남아 있습니다.
- 휴식 체크는 **이 기기의 설정과 입력한 경기 투구수**로 계산한 참고 정보입니다. 실제 리그 규정, 훈련 투구량, 몸 상태나 등판 가능 여부를 판정하지 않습니다.
- HTML 정리는 알려진 실행 경로를 제한하지만 임의의 외부 HTML을 완전히 신뢰하도록 만드는 기능은 아닙니다. 출처를 확인한 글을 사용하세요.
- 검색 제외 설정은 접근 통제가 아닙니다. 저장소와 공개 JSON의 접근 범위는 기존 설정을 따릅니다.

## 2026-10 화면·정확성 개선

핵심 기록을 먼저 보여주고 상세 통계를 접어 화면 밀도를 낮췄습니다. 모바일에서는 카드와 입력 요소를 재배치했습니다. 빈 타석의 기본 안타, 타자 경계를 넘는 연속 볼, 포지션별 경기 수, 볼넷/사구 지표 구분을 바로잡았습니다. 훈련 수정은 저장 전까지 원본을 유지하고, 명시적 백업 병합은 칼럼과 삭제 이력도 함께 다룹니다.

## 드래프트 자료 (2026-11-02 재검토)

- `draft-data.js`: 2023~2027년 1~5라운드 250명의 공식 지명 사실, 행별 출처 ID, 공개 경로 50명.
- `draft-page.js`: 동일 자료에서 표·포지션·구단·소속 집계를 계산합니다. 개인 경기 저장소에는 접근하지 않습니다.
- `draft-2023-2026.html`: 예전 링크를 최신 `/#draft` 화면으로 연결합니다. `#draft-board`, `#draft-schools`, `#draft-routes`, `#draft-sources`도 직접 열 수 있습니다.
- `tests/fixtures/draft-official.tsv`: 공식 PDF·연감에서 별도로 전사한 250행 검증 기준. 출처는 `draft-data.js`와 [검토 기록](DRAFT-AUDIT.md)에 있습니다.
- 소속 분류는 고교 단계(고교 연령 팀 포함) / 국내 대학(얼리 포함) / 기타(해외 대학·해외 프로 경력·독립구단)입니다. 이것을 학교별 성공률로 해석하지 않습니다.

자료를 고칠 때는 해당 행의 출처를 먼저 확인하고 데이터와 검증 기준의 변경 이유를 함께 기록하세요. 초·중 단계의 미확인 항목은 추정하지 않습니다. 원본 연감/PDF·개인정보가 포함된 조사 HTML은 배포하지 않습니다.

## 칼럼 읽기 양식 (2026-11-02)

현재 공개 칼럼 3편의 제목·본문·표·여백을 `#p-posts` 안의 CSS로 통일했습니다. 밝은 배경에 짙은 글자, 모바일 본문 16px, 좁은 화면의 표 스크롤을 적용했습니다. 저장된 원문·도해·링크와 `data.json`은 변경하지 않았습니다. 이 변경은 읽기 양식 정리이며 칼럼 내용에 대한 추가 사실 검증을 뜻하지 않습니다.


## 개인 스코어북과 기록 입력 (2026-11-11)

- 경기 일지에 타석 순서, 결과 기호·한글명, 타점·득점, 입력된 타구 방향·유형, 펼쳐보는 투구 순서를 표시합니다. 다이아몬드의 색은 타석 시작 주자만 뜻합니다. 타격 이닝·아웃카운트·수비 처리·진루 경로는 추정하지 않습니다.
- 새 주자 입력은 `bases: [1, 2, 3]` 중 실제 선택한 루를 배열로 저장합니다. 빈 배열은 주자 없음입니다. `run` 요약값도 함께 저장해 기존 집계·백업과 호환합니다.
- 기존 `none`·`first`·`risp` 기록을 읽을 수 있습니다. 기존 `risp`는 정확한 루 미기록 상태로 유지하며, 명시적으로 루를 선택하거나 주자 없음을 누르기 전에는 빈 배열로 바꾸지 않습니다. 득점권 타율은 2루 또는 3루가 있거나 기존 `risp`일 때 타수·안타로 계산합니다. 볼넷 등은 타수에 넣지 않습니다.
- 투구 입력의 등판 상황·투수 승패와 훈련 메뉴를 제거했습니다. 기존 역할·승패·옛 투구 합계·훈련·추가 필드는 유지합니다. 훈련 내역은 백업 및 CSV 내보내기로 남아 있습니다.
- PO와 A는 직접 아웃/아웃을 도운 송구로 풀어 쓰고 유격수→1루수, 뜬공, 포수 삼진 포구 예시를 제공합니다.
- 경기 일지 상단에 기존 집계와 같은 9이닝 기준 ERA를 추가했습니다. 투구 아웃이 0이면 기존처럼 `–`로 표시합니다. 타율·OPS·탈삼진·누적 투구수는 그대로 제공합니다.
- `data.json`은 이 기능 변경에서 수정하지 않습니다.

추가 DOM 통합 테스트는 jsdom 26.1.0이 설치된 개발 환경에서 `node tests/scorebook.dom.cjs`로 실행합니다. 합성 데이터만 사용하며 외부 저장은 막고, 체크박스 8가지 조합·임시저장 복구·기존 기록 수정/저장·반복 초기화를 검사합니다. 실제 브라우저의 화면 배치 검사는 별도입니다.
